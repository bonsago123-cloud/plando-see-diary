# T07 검증 범위

검사일: 2026-10-26 (Asia/Seoul). 검사 대상은 이번 ZIP의 소스입니다. GitHub 업로드·커밋·푸시·Vercel 배포·운영 DB 변경은 수행하지 않았습니다.

## 완료한 로컬 검사

- 자동 테스트 29개 통과: 기존 기능 회귀, 로그인/회원가입 DOM 모의 검사, 서버 기록 페이지 로그인 강제, 인증·소유자 분리 통합 검사, 서울 날짜별 실제 시간 평균
- TypeScript 자료형 검사 및 Next.js 배포 빌드 통과
- 소스 패턴 검사 47개 파일 통과, Git diff 공백 오류 검사 통과
- 두 임시 계정의 계획·할 일·실행 기록·주제·생각 단건 읽기와 모든 변경 action 양방향 거절
- 정상 소유자의 읽기·수정·삭제, 목록/내보내기 분리, query/header/body의 계정 위조, 거절 전후 데이터 전체 내용 비교
- 로그아웃/비밀번호 변경/만료 후 세션 거절, 계정 삭제 및 DB 오류 시 삭제 전체 롤백
- 이전 익명 자료가 첫 가입자에게 자동 할당되지 않음, 관리자 명시적 이전 및 반복 실행

`docs/auth-test-results.md`는 실제 NextRequest/NextResponse와 PostgreSQL(PGlite) 실행 기록을 마스킹하여 남긴 것입니다. 네트워크 전송 자체는 모의 환경이므로 실제 운영 HTTP 캡처라고 표시하지 않습니다. 비밀번호 해시 두 개는 임시 시험 계정의 값이며 계정은 테스트가 끝나면 폐기됩니다.

## 짧은 확인 방법 4줄 — 기능 안내

1. 어디로 가나요: 본인이 배포한 결과물의 `/login`으로 갑니다(실제 URL은 배포 후 기입).
2. 세 단계 안에 무엇을 하나요: 시험 계정 가입 → 로그인해 계획 하나 저장 → 로그아웃 후 `/diary` 접속.
3. 무엇이 보이면 통과인가요: 로그인 뒤 본인 계획이 보이고 로그아웃 뒤에는 로그인 화면이 나옵니다.
4. 안 될 때는 무엇이 보이나요: 잘못된 로그인은 동일한 오류 문구, 비로그인 자료 요청은 401, 남의 자료 요청은 404가 나옵니다. 서버 설정 오류는 안내 메시지가 표시됩니다.

네 줄은 확인 방법이며, 사람이 실제로 통과를 확인했다고 작성한 결과가 아닙니다. 타인 자료 분리와 세션 재사용 확인은 인증 설명서 및 자동 검사 기록의 상세 요청을 참고하세요.
