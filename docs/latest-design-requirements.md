# 설계(6) 기준 구현 범위

기준은 사용자가 마지막에 제공한 「플랜두씨 설계(6).txt」와 「과제6 조건 및 목표.txt」 두 파일뿐입니다. 기존 원본 커밋 964e67fb7ded2185ec122ab511f36f8ae9364c4e에서 별도 작업을 시작했습니다. 이전 수정 ZIP은 사용하지 마세요.

## 설계 이념

기존 색상, 카드, 버튼, 편집창, 메뉴 구조를 유지합니다. 달력은 월별 화면과 날짜별 목록으로 한정합니다. 불필요한 상태나 새로운 대시보드·통계 화면을 추가하지 않습니다. 기존 명언, 마음 회복, 시간 비교, 실행 기록 편집·삭제는 유지합니다.

| 최신 설계 요구 | 구현 |
|---|---|
| 모든 드롭박스 휠·좌클릭 드래그 | 공통 Choice; 휠 스크롤, 누른 채 위아래 끌기, 키보드 방향키/Enter/Escape |
| 편집 시 저장된 날짜·시간 | DateChoice에 기존 form 값을 전달; 년/월/일/시/분을 저장값에서 표시 |
| 왼쪽 캘린더 | 월 이동·오늘·종류 필터·날짜별 기록; 계획/할 일/실행/주제/생각 표시 |
| 단순한 달력 | 날짜 칸에 최대 3개, 나머지 개수 표시; 선택 날짜에서 전체 목록 확인·편집 |
| 완수한 계획 목록 | 계획 목록/완수한 계획 두 목록; 카드의 완수 처리/완수 해제 버튼 |
| 사용자 카테고리 | 계획 편집에서 기존 카테고리 선택 또는 새 카테고리 생성 |
| 카테고리 필터 기본 전체보기 | 두 계획 목록에 같은 필터 적용, 미지정도 선택 가능 |
| 나의 생각: 주제 아래 생각 | 주제 선택 후 생각 목록, 각각 추가/수정/삭제 |
| 주제·생각 이름과 기간, + 내용 칸 | 각 편집창에서 이름·시작일·종료일과 내용 칸 추가/삭제 |
| 기존 UI와 기능 유지 | 기존 할 일 상태 예정/진행 중/완료와 집계 유지 |

설계의 ‘그리고 기한을 넘겨서 실행기록을 기록했는데 지연’ 문장은 미완성입니다. 임의의 새 규칙을 만들지 않고 과제 T06-C30을 따릅니다. 마감일이 서울 기준 오늘보다 앞서고 아직 완료하지 않은 할 일만 지연입니다. 실행 기록 추가는 완료 전환과 별개이며, 완료하면 지연에서 제외됩니다.

내용 칸은 요청 크기 관리를 위해 각 주제/생각당 20개, 칸마다 2,000자까지입니다. 주제/생각의 종료일을 포함해 달력에 표시하며 생각의 기간은 주제 기간 안으로 강제하지 않습니다. 계획 완수는 할 일의 완료율과 별개로 사용자가 직접 지정합니다.

## 짧은 확인 방법 4줄

1. 어디로 가나요: 적용 후 사이트의 내 계획 → 할 일 관리 → 실행 기록 → 돌아보기, 캘린더, 나의 생각을 엽니다.
2. 세 단계 안에 무엇을 하나요: 직접 만든 계획에서 할 일 추가 → 실행 기록 저장 → 완료 처리 후 돌아보기를 엽니다.
3. 무엇이 보이면 통과인가요: 계획 이력과 실제 기록이 구분되고 완료가 한 번 집계되며, 숫자를 눌렀을 때 근거가 보이고 새로고침 후 같은 값이 남습니다.
4. 안 될 때는 무엇이 보이나요: 화면의 오류 안내를 확인합니다. 목록이나 집계가 다르면 해당 요구는 통과로 기록하지 않습니다.
