새 검사는 실제 API 코드를 불러와 DB 연결만 로컬 PGlite(PostgreSQL 엔진)로 대체했습니다. SQL 저장과 재조회, 추가 마이그레이션 2회 실행, 최초 계획 이력 보존, 완수 중복 요청의 이력 중복 방지, 카테고리 저장·다음 계획 전달, 실행 시간 계산, 완료 중복 방지, 지연 제외, 주제/생각 저장과 삭제·내보내기를 확인했습니다.

화면 검사는 JSDOM에서 React 컴포넌트를 실행했습니다. 저장된 날짜·시간 표시, 윤년 변경, 방향키 선택, 포인터 드래그로 스크롤하되 선택값을 바꾸지 않는 동작, 계획/완수한 계획 목록 분리, 기본 전체보기 필터, 할 일 편집 저장값, 달력 42칸, 주제 내용 칸 추가를 확인했습니다. JSDOM에는 실제 레이아웃과 마우스 휠의 브라우저 기본 동작이 없으므로 이 결과를 실제 브라우저 검증으로 간주하지 않습니다.

기존 할 일 상태 모듈, 상태 테스트, 집계 모듈은 원본과 같습니다. 최신 설계에서 요청하지 않은 실패 상태나 상태 이름 변경은 추가하지 않았습니다.
